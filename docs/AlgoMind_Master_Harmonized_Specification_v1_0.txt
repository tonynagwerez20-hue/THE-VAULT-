2. System Definition
AlgoMind is a regime-aware retail trading research and execution system for instruments including XAUUSD, EURUSD and BTC. It combines market structure, liquidity, auction/value context, VWAP, imbalance/FVG, proxy order flow, news, options/dealer positioning and CFTC/COT positioning as evidence streams.
The system is not defined as an AI bot first. Its primary product is a deterministic information and decision engine whose decisions can be reconstructed from timestamped inputs. ML and external intelligence are additive layers, not substitutes for causal data handling, explicit hypotheses or risk controls.

4. Non-Negotiable Engineering Principles
No look-ahead: future bars, final object state, later invalidation, future FVG fill or future reaction windows cannot alter historical features.
Closed-bar causal processing: forming bars may be refreshed for live observation but become historical only when finalized.
One canonical vocabulary: every feature/event has a definition, unit, source, timestamp rule and version.
Python cannot bypass MQL5 risk or execution authority.
Proxy honesty: candle/tick-derived delta is labelled proxy delta and never represented as exchange cumulative delta or institutional DOM.
Regime before optimization: establish the market environment before selecting the strategy hypothesis.
Fail closed: critical uncertainty, stale external data, schema mismatch, invalid inference or clock mismatch means NO_TRADE.
NO_TRADE is a valid output, not a system failure.
ZeroMQ is transport, not strategy.
ML is a gate/ranker until robust incremental value is demonstrated.
Every performance claim must survive out-of-sample and walk-forward testing.

7. Point-in-Time Event and State Model
Every stateful object must be represented as state-as-of-bar-b when queried historically. Mutable final-state fields are forbidden as historical feature inputs.
Each event has creation timestamp/bar, active interval, state transitions and expiry/invalidation rules.
OB/FVG/liquidity lifecycle snapshots are maintained one closed bar at a time.
Historical queries read snapshots, never final mutable object state.
Backfill initialization must replay the same causal process used during incremental operation.
A newly detected object enters forward maintenance on the same causal schedule; no newest-object exclusion.
Sweep reaction becomes available only when the allowed reaction window has elapsed.

10. CFTC/COT Positioning Specification
CFTC/COT is a slow-moving external positioning context layer, not an intraday trigger. The adapter must preserve both the report/reference period and the actual public release/availability timestamp. A COT observation may be used historically only after it was publicly available.
Maintain immutable raw CFTC releases and normalized records.
Separate report date from publication/availability timestamp.
Never backfill revised data into an earlier decision timestamp.
Map futures contracts to traded instruments explicitly; mappings are versioned and auditable.
For XAUUSD, document the selected gold futures proxy and basis assumptions.
For FX, document currency-futures mapping and sign convention.
For BTC, document the selected CFTC-covered futures contract and mapping if used.
Compute positioning percentiles/extremes only from observations available at the decision time.
CFTC may modify context/regime confidence but cannot override hard risk.
Prove incremental out-of-sample value before CFTC context is allowed to influence live decisions.
11. Options / Dealer Positioning Specification
Options data is identified by source, observation timestamp, expiry, strike and underlying mapping.
Possible fields include premium, open interest, Delta, Gamma, IV, ATM distance and concentration.
Options positioning is context/location information, not a guaranteed support/resistance level.
Use expiry selection consistent with trading horizon and inspect relevant nearby strikes.
Derived states may include touch, rejection, reclaim, acceptance and failure.
Options context modifies regime/hypothesis scoring; MQL5 retains final execution authority.
Missing or stale options data is explicitly ABSENT/DEGRADED, never silently converted to a neutral zero.
Any numerical threshold is a research parameter and must be validated.

14. Strategy Hypotheses
14.1 Continuation
Requires compatible structural direction, participation/pressure confirmation and a valid entry location.
May use BOS/CHOCH, displacement, FVG/OB retest, VWAP/value position and order-flow confirmation.
External options/CFTC/news context can modify confidence but cannot override structural invalidation or hard risk.
14.2 Mean Reversion
Requires balanced/rotational conditions, stretched price relative to value/liquidity and rejection/absorption evidence.
Evidence may include VWAP/value deviation, liquidity sweep, FVG/OB reaction, delta reversal and options context.
Invalidates when the market transitions into confirmed expansion/trend conditions.
15. Proxy Order Flow
Proxy A and Proxy B have explicit mathematical definitions and source labels.
Fusion specifies weights and version and is deterministic.
Features include delta flip, surge, transition, divergence and persistence where causally measurable.
No proxy is described as true exchange footprint, DOM or institutional cumulative delta.
External order flow, if later available, is an additional evidence source and does not silently replace the proxy.

17. Execution Contract
Validate symbol/trading mode, spread, margin, exposure, daily loss, total drawdown, stops level and slippage conditions.
Run OrderCheck before order submission.
Classify trade-server retcodes.
Verify ResultDeal/fill price/volume when available.
Do not blindly retry rejected orders.
Mutate internal position state only after confirmed execution/reconciliation.
After connection interruption, reconcile actual account state before a new order.
Prevent duplicates using decision/setup/position identity.
18. Position Management and Reconciliation
Use POSITION_IDENTIFIER as the stable position key where applicable.
Persist state required for partial close, break-even and trailing.
Use OnTradeTransaction as the authoritative transaction stream for fills, partials, modifications, closures and realized P/L.
Restart must restore safe state without duplicate orders.
Actual account state outranks stale local assumptions.

21. ML Architecture
ML is introduced only after deterministic baseline and feature integrity are proven.
Initial role is gate/ranker, not signal generator.
LightGBM/statistical models are suitable for the first production research layer.
River/online learning is optional and cannot receive direct execution authority.
Inference fails closed on load errors, NaN/out-of-range output, missing calibration, schema mismatch or model mismatch.
Ship a manifest containing feature names/order, schema version, model version and integrity hash.
Training and serving must use identical feature geometry, especially SL/RR assumptions.

33. Final Architectural Position
AlgoMind should be built as a deterministic MQL5-first trading system with a controlled Python intelligence/research boundary. Native market, structure, auction, proxy order-flow, regime, strategy, risk and execution logic remains in MQL5. Python handles capabilities that MT5 cannot natively provide or that are substantially better suited to Python: CFTC/COT, options/dealer positioning, external news/order-flow, dataset construction, model research and parity testing.
The critical milestone is not profitability first. It is proving that the same historical information produces the same feature state and decision in deterministic replay, MT5 Strategy Tester and live-style operation. Only after that proof should additional complexity—external feeds, ZeroMQ, ML and scaling infrastructure—be allowed to increase.
